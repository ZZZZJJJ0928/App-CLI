# 邮件学习窗口与 QQ 重放原型

[English](MAIL-NATIVE-SEND-PROTOTYPE.md)

这是默认关闭的本地原型，尚未经真实服务商发信验证。现有新建、回复和附件发信继续走
托管 DOM 流程，不新增公共命令或输出 schema。

## 学习证据

Reader 的 `armLearning` 窗口现可记录同源 XHR/fetch 变更的有界响应结构，以及 Outlook
Worker/MessagePort 操作。Outlook 发送页的 binding 会在导航前安装早期 worker 钩子。
观察过程不确认、不消费、不重放网页自身回调；请求 ID 仅在页面内存中用于关联。

请求必须在当前窗口开始；前一窗口迟到的回包不会归入新窗口。每个窗口最多 120 秒、24 条记录。
响应读取上限为 1 MiB 和 5 秒，包含分块响应；结构遍历限制深度、宽度和节点数，每条最多 8 KiB。
只记录已知结构字段、值类型和长度档位，不认识的响应键归为 `dynamic_key`。
区分 JSON/XSSI、文本、标记文本、空响应及超限响应；邮件正文、地址、令牌、请求 ID 和响应值
均不作为证据输出。`APP_CLI_MAIL_LEARNING_EVIDENCE=1` 在托管操作后输出形状日志。

## QQ 重放范围

`APP_CLI_MAIL_NATIVE_SEND=qq_mail` 显式开启托管适配器中的原型。
它要求同一账号的 QQ 页面仍然打开，且已学习并独立确认一次 DOM 发信。冷页面沿用原有 DOM
流程。本原型不创建常驻变更页面、不修改 Host 页面生命周期；每次发送都关闭页面的部署无法复用模板。

仅支持单收件人、无抄送、无附件、纯文本的新建邮件。观察到的 `/send/sendmail` 表单必须恰好
包含已知的 18 个字段名。重复或未知字段、密送、附件/回复元数据、恢复草稿、日历动作、回执请求、
发件账号不符、未知内容类型和跳转均拒绝。离线夹具中的字段值和收件人编码假设仍待实机验证。

模板学习独立于形状记录：必须为合格发信显式布置，原有 DOM 已发送证据通过后，才由
`confirmSendTemplate` 提升模板，并核对观察到的收件人和主题。会话字段只保存在页面内存；
原收件人、主题、正文、草稿 ID 会被清除。过期、账号变化、页面释放均清除模板；每份已确认模板
最多派发一次。

重放替换收件人、主题和转义后的正文，清空旧草稿 ID，使用页面同源 fetch，30 秒超时且禁止跳转。
派发继续经过既有授权释放与持久化、只创建一次的发送 journal。派发后不回退点击、不自动重试，
丢失响应、重启、对账也不例外。

**所有原型重放结果都保持 `unknown`，包含 HTTP 200 / `ret=0`。**
真实发信响应标识与独立的原生已发送列表核对尚未合格，因此原型不能生成 `sent` 回执。
当前用于验证请求构建与派发语义，不能据此宣称已送达或耗时已改善。

## 本地验证及下一门禁

测试只使用合成账号、虚拟页面传输及临时 journal，不发送邮件。覆盖序列化 Reader/worker 钩子、
脱敏、上限、窗口关联、模板资格/过期、参数替换、并发尝试、授权拒绝，以及重启/对账不二次派发。
原有 DOM 发信与收信测试继续包含在完整 runtime 套件中。

启用真实重放前，先取得部署及新测试信的批准，再记录真实响应形状、识别服务商邮件 ID，
以独立原生已发送读取核对同一 ID，并验证会话过期和同页复用。不得重发历史 unknown 邮件。
回复、附件、Outlook 重放和 Gmail 重放不属于本原型。

2026-10-22 本地验证（macOS、Node 26.2.0、Python 3.11）：runtime 在
`--test-concurrency=1` 且启用恢复用例时 **508/508**，Python **90/90**；
生成 userscript/binding 与公开树检查通过。本机测试需使用规范临时路径
`TMPDIR=/private/tmp`，默认临时路径为符号链接，会触发未修改基线中已有的 capture 检查失败。
同时运行基线与候选完整套件时，两个短时限 executor 用例也会失败；候选完整串行运行零跳过通过。
